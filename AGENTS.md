# Правила работы с проектом

- До изменений прочитайте `README.md`, `DEPLOYMENT.md` и `docs/functional-contract.md`.
- Без прямого запроса сохраняйте назначение проекта, основные взаимодействия, внешний вид, legacy URL и исходный seed-набор.
- Не меняйте код только ради согласования с устаревшей документацией: сначала зафиксируйте расхождение.
- Первичная инициализация новой пустой локальной SQLite-базы через Docker Compose может выполнять migrate и seed без предварительного backup. Существующую локальную или production-базу нельзя удалять, сбрасывать, мигрировать или повторно заполнять seed-данными без проверки состояния и последствий; перед операциями, способными изменить существующие постоянные данные, обязателен согласованный backup.
- Owner-доступ должен оставаться закрытым по умолчанию: пустой `OWNER_PASSWORD_HASH` не может разрешать изменяющие действия, а `/login` не добавляется в меню без отдельного решения.
- После изменений кода, конфигурации, зависимостей или схемы выполните `docker compose exec app composer test`. HTTP-smoke для `/`, `/up`, основных публичных страниц, `/login` и 404 выполняйте, если изменение может повлиять на runtime или внешнее HTTP-поведение. Для изменений только документации достаточно проверить ссылки, согласованность документов и `git diff --check`.
- Если изменение делает документацию неточной, обновите соответствующий документ в той же задаче.
