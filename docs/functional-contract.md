# Функциональный контракт 99 Bottles

Этот документ фиксирует поведение современной Laravel-версии, которое без прямого запроса считается совместимым с исходным проектом 2010 года.

## Коллекции и исходные данные

## Доступ и действия

Публично доступны главная страница, списки и карточки всех коллекций, поиск и форма входа. Любой посетитель может просматривать данные и запускать анимацию песни.

Только owner может:

- добавлять, редактировать и удалять напитки;
- добавлять и удалять наполненные бутылки;
- открывать страницы подтверждения соответствующих изменений.

Owner-аутентификация использует один password hash из `OWNER_PASSWORD_HASH` и флаг `owner_authenticated` в сессии. Успешный вход регенерирует session ID; выход инвалидирует сессию. POST `/login` ограничен пятью попытками в минуту, а изменяющие формы защищены CSRF.

Если `OWNER_PASSWORD_HASH` пуст, middleware отвечает `503` даже для сессии со старым owner-флагом. Это fail-closed поведение является обязательным. Адрес `/login` намеренно отсутствует в меню.

Ссылки редактирования и удаления, а также раскрываемые формы добавления видимы гостям как часть сохранённого интерфейса. Попытка выполнить защищённое действие перенаправляет гостя на `/login`; защита не должна зависеть от скрытия элементов в браузере.

## Поиск и AJAX

`GET /search` показывает пустую форму результатов. Поиск выполняется через `POST /search`; запрос обязателен, ограничен 255 символами и обрезается по краям.

Строка разбивается по Unicode-пробелам. Все непустые слова должны присутствовать в объединённых названии и описании напитка — логика AND. Сравнение регистронезависимо для кириллицы. Результаты сортируются по ID. Отдельного Lucene- или другого поискового индекса нет.

`GET /beverages/{id}` и `GET /bottles/{id}` при заголовке `X-Requested-With: XMLHttpRequest` возвращают только HTML-фрагмент без общего layout. На странице `/filledbottles` такие ссылки открываются в overlay; при ошибке показывается `loading error`. Обычный запрос по тем же URL возвращает полную страницу.

## Стабильные URL

| Метод и URL | Доступ | Поведение |
| --- | --- | --- |
| `GET /` | публичный | Главная и песня с бутылками |
| `GET /beverages` | публичный | Список напитков и раскрываемая форма добавления |
| `POST /beverages` | owner | Создание напитка |
| `GET /beverages/{id}` | публичный | Полная или AJAX-карточка напитка |
| `GET /beverages/edit/{id}` | owner | Форма изменения напитка |
| `POST /beverages/edit/{id}` | owner | Сохранение напитка |
| `GET /beverages/delete/{id}` | owner | Подтверждение удаления напитка |
| `POST /beverages/delete/{id}` | owner | Удаление напитка с каскадом связей |
| `GET /bottles` | публичный | Список бутылок |
| `GET /bottles/{id}` | публичный | Полная или AJAX-карточка бутылки |
| `GET /filledbottles` | публичный | Список и раскрываемая форма добавления |
| `POST /filledbottles` | owner | Создание наполненной бутылки |
| `GET /filledbottles/delete/{id}` | owner | Подтверждение удаления |
| `POST /filledbottles/delete/{id}` | owner | Удаление наполненной бутылки |
| `GET /search` | публичный | Форма поиска без результатов |
| `POST /search` | публичный | Поиск по напиткам |
| `GET /login` | публичный, скрыт из меню | Форма входа или состояние owner-сессии |
| `POST /login` | публичный, throttled | Проверка пароля и создание owner-сессии |
| `POST /logout` | сессионный | Инвалидация текущей сессии |
| `GET /up` | публичный | Health endpoint, `200` при исправном приложении |

Неизвестный URL и отсутствующий model ID возвращают `404`, используя страницу с текстами `An error occurred` и `Page not found`.

## Намеренно сохраняемый интерфейс

- XHTML doctype, фиксированная ширина страницы 800 px и визуальная стилистика исходного сайта.
- Смешанные русские и английские подписи, меню `Main (sing)`, `Filled Bottles`, `Bottles`, `Beverages` и footer `especially for bankir.ru`.
- Отдельная поисковая форма справа на каждой полной странице.
- Старые action-style URL и написание `/filledbottles` без дефиса.
- Формы добавления скрываются и раскрываются JavaScript без смены URL.
- `sing!` запускает последовательное падение бутылок, `stop!` приостанавливает, `once more!` перезагружает главную.
- Анимация заменяет изображение упавшей бутылки обломками только в DOM и никогда не удаляет запись из SQLite.
